## Build script (`scripts/build_site.py`)

8. `stamp()` (`:557`) silently no-ops if a page loses its stamp markers and
   `--check` still passes — assert ≥1 substitution per static page and/or make
   the STAMPS regexes attribute-order tolerant.
9. `render_llms_log_section` (`:456`) interpolates entry titles raw into
   Markdown — a `[`/`]` in a title breaks the llms.txt link. Add bracket escaping.
10. `MARKER` regex (`:73`) excludes digits — a future `BUILD:NAV2:START` marker
    never matches. Widen `[A-Z-]+` to `[A-Z0-9-]+` (one character).
11. Orphan cleanup (`:634`) deletes any `log/*.html` not in the planned set —
    a hand-authored page dropped into `log/` is destroyed silently. Restrict
    deletion to files bearing a generated-by marker.
12. Decide committer-date (`%cI`) vs author-date (`%aI`) semantics for
    `last_modified` before entries accumulate; also consider
    `max(fragment_date, template_date)` so template-only changes don't rewrite
    entry pages without bumping feed/sitemap dates.
13. Single-pass lastmod: even cached, the build forks ~20+ `git log` calls.
    One `git log --format=%cI --name-only` pass would be O(1) subprocesses —
    worth it once entry count grows.
14. Minor: `render_entry` passes an unused `modified_human` kwarg; duplicate
    meta keys silently overwrite (last wins) unlike the rest of meta validation.

## Data contract / validator

15. **Timezone semantics of "future"**: `date.today()` is local; CI is UTC. A
    contributor east of UTC appending early morning gets a legit observation
    rejected. Pick a policy (explicit UTC, or 1-day tolerance) and document it
    in SCHEMA.md.
16. Pass `parse_constant=` to `json.loads` in the validator so `NaN`/`Infinity`
    are invalid JSON outright (belt-and-braces over the new field checks).
17. `append_observation.py --mode` default: after transitioning to `live`, the
    `paper` default makes every append fail until `--mode live` is passed.
    Default to the mode implied by `mode_changes`.
18. Exit-code collision: the append script's docstring says 2 = "could not run",
    but argparse also exits 2 on usage errors. Map argparse errors to 1 or amend
    the doc.
19. `--note` is silently ignored on plain appends (only meaningful with
    `--mode-change`) — error on the combination.
20. Workflow: empty `git merge-base` (orphan branch) yields a confusing
    "cannot resolve ''" — handle explicitly
    (`.github/workflows/validate-track-record.yml:69-72`).
