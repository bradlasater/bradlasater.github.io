Docs section

living document · maintain by hand
docs/*.html · docs/site.css · scripts/build_site.py

docs/ is the section you are reading. It publishes the repository's Markdown documentation — the README, the roadmap, the track-record data contract, the audits, and the research notes — as dark, indexed HTML pages under /docs/, so the project's paper trail is readable on the site itself rather than only on GitHub. The Markdown files are the source of truth; every page here is a hand-maintained copy of one.

Invariants

These hold on every page in the section, mirrors and originals alike. Nothing enforces them except you — there is no CI check — so they are the first place to look when a page looks wrong.

  • The sidebar is byte-identical on every page. The whole <nav class="toc"> block is the same text everywhere, with exactly one class="active" marking the current page. Verified today by hashing the block with the active class stripped: all pages agree. When you add a page, you edit this block on every page — see below.
  • Every mirror carries the drift warning. A <p class="meta-note"> directly under the header: This page mirrors <path>; edit the Markdown, then re-sync this page. Original pages (the index, the section pages) do not carry it; their .meta block says living document · maintain by hand instead.
  • External links open in a new tab. Every off-site anchor gets target="_blank" rel="noopener". Internal links are relative (section-vol.html).
  • Headings are deep-linkable. Every h2 has a slugified id (<h2 id="the-append-only-invariant">) so audit items and cross-references can point into a page.
  • The build never touches these pages. They are hand-authored, carry no stamp markers, and reach sitemap.xml only through docs_pages() discovery. Rebuilding the site cannot clobber them.

Adding and re-syncing pages

Add a new mirror

  1. Copy the shell from an existing mirror — the head boilerplate, fonts, skip link, and sidebar are verbatim; change only <title>, the description, canonical, og:url, and og:title.
  2. Set the header .meta to mirrors <path> and add the .meta-note drift warning naming the Markdown source.
  3. Move class="active" onto your new sidebar item.
  4. Add the sidebar item to every page in the section. This is the painful part: today that is thirteen files, by hand, byte-identically. Do not hand-edit each one — write the block once and splice it in with a script (the block is delimited by <nav class="toc"> … </nav>, and the active class is the only per-page difference, so a small Python loop over docs/*.html does it safely).
  5. Rebuilding the site picks the page up automatically: docs_pages() globs docs/*.html, so the new page lands in sitemap.xml on the next build with no second edit.

Re-sync a mirror after editing its Markdown

There is no pipeline — the sync is you. Edit the Markdown, then hand-port the changes into the mirror: same heading ids for the same sections, keep the drift warning intact. For large edits it is faster to regenerate the body from scratch (copy the shell, rewrite the <main> content) than to patch. The research-note mirrors show the pattern: tables stay tables, fenced code becomes pre, quotes become blockquote.
