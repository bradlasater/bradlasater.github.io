living document · maintain by hand

Purpose

bradlasater.com is a recruiting instrument, not a blog: a static GitHub Pages site aimed at quantitative finance roles, built around an in-development systematic volatility research and execution platform and — more importantly — the research process behind it. Everything on it exists to make one case to a hiring manager: here is a person who does the work in the open, writes it down, and holds himself to a public, unrevisable track record. This page is the whole site on one screen. Read it first; the six section pages go deeper.

How the pieces fit

Three scripts own derived files. The single most useful habit this page can give you: before editing anything, check whether one of these owns it — if so, edit the source and re-run the script instead.

Pipeline Owns (never hand-edit) Runs when
scripts/build_site.py log/<entry>.html, the entry list in log/index.html, feed.xml, sitemap.xml, the log section of llms.txt, and the lastmod/dateModified timestamps stamped into every page Pre-commit hook, and CI (--check) fails a push that leaves its outputs stale
scripts/sync_docs.py Everything in handbook/ — copied from the private data_ingest_infra repo and re-skinned into the site theme at sync time By hand only. Deliberately not in the hook or CI: neither has the private source repo, so neither can detect drift
scripts/journal_prompts.py The prompt table between the PROMPTS markers and the GENERATED stamp in journal-prompts.html; the surrounding guide is hand-authored launchd, daily at 06:00 ET, from recent git activity in this repo and data_ingest_infra

The fourth data flow has no generator: scripts/append_observation.py appends one dated day to data/track-record.json (its own dated commit), CI validates the append-only invariant, and assets/js/track-record.js computes every statistic in the browser at view time. Nothing is precomputed, so the rendered record cannot disagree with the data file.

Conventions and gotchas

  • The append-only invariant is the point of the site. Never force-push, never rebase or amend a commit that published an observation, never edit a published number — append a correction instead. CI walks every commit and rejects history rewrites, but the rule is yours to keep. See the data contract.
  • The nav is hand-maintained in eight places. Seven HTML files (index.html, cv.html, 404.html, vol/index.html, vol/methodology.html, vol/track-record.html, log/index.html) plus the nav() function in scripts/build_site.py, which stamps it into generated log pages. Change one and not the rest and the site drifts visibly. Handbook pages are the exception: they keep their own sidebar and link back out.
  • The header stacks below 56rem, and that number is measured, not round. Brand plus seven items fit at 880px and wrap at 850px. Adding or renaming a nav item without re-measuring strands the GitHub link on its own line and reads as broken.
  • Root-relative paths everywhere. Opening index.html over file:// does not work — stylesheets are root-relative and track-record.js uses fetch(). Develop through python3 -m http.server.
  • British spelling in prose. Deliberate exceptions: JSON-LD (American, for search) and proper nouns spelled as the institution spells them.
  • Docs pages mirror Markdown. Most pages in /docs/ mirror a Markdown file in the repo — edit the Markdown, then re-sync the mirror. The section pages (this one and its six siblings) are the exception: original, maintained by hand.

Golden rules

  • Never force-push this repository. The track record's entire value is that history cannot be revised; the git log is the timestamp trail, and no file-level check can detect a rewrite after the fact.
  • The nav lives in seven HTML files plus nav() in scripts/build_site.py. Edit all of them or the generated log pages drift from the static ones.
  • handbook/ is synced, never edited. Edit the source in data_ingest_infra, then run python3 scripts/sync_docs.py.
  • Docs mirrors: edit the Markdown source, then re-sync the HTML. The page name says which file it mirrors.
  • Run python3 scripts/build_site.py before pushing (the pre-commit hook does it for you) — CI's --check fails on stale derived files.
