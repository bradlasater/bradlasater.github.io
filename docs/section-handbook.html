Handbook & sync

living document · maintain by hand
handbook/ · scripts/sync_docs.py · assets/css/handbook-chrome.css

Purpose

handbook/ is the published copy of Crack the Sky, the system handbook for the running ingest box. It is authored in a different, private repository (data_ingest_infra/docs), kept next to the code it describes so the two are edited in the same commit — moving it here would break exactly the property that makes it trustworthy. This repository therefore owns none of the content: scripts/sync_docs.py copies the source over, re-skins it into the site's design system, adds the metadata a public URL needs, and treats handbook/ as derived output.

Rule. Never hand-edit anything under handbook/. Every file there is overwritten from source on each sync, and anything that no longer exists upstream is deleted. Every synced file carries a banner comment saying so. The edit belongs in the source repository, followed by python3 scripts/sync_docs.py and a commit here.

How it works

Run python3 scripts/sync_docs.py (optionally --source DIR; default ../data_ingest_infra/docs). The script builds the full planned output in memory, then for each file:

  • Classify. .html files go through transform_html(), .css files get a banner plus the reskin, and any other file type aborts the run — add a rule rather than copying blind. A missing index.html upstream is also fatal, since /handbook/ would 404.
  • Swap the fonts stylesheet first. The upstream Google Fonts URL names IBM Plex and would trip the reskin's own tripwire, so it is rewritten to the site's Inter / JetBrains Mono / Newsreader URL before anything else.
  • Reskin. FONT_MAP (IBM Plex Mono → JetBrains Mono, IBM Plex Sans → Inter) and COLOR_MAP (the handbook's warm hex palette → the site's OKLCH tokens, status-chip borders and timeline bars included) are applied as literal string replacements to every synced file, diagrams and inline styles included. Two categorical source colours (#7aa3b0, #4d7380) survive deliberately — they encode REST vs S3 identity in the diagrams. Anything unrecognised — a leftover hex colour, an unmapped font-family — fails the sync loudly instead of quietly publishing a page in the old theme.
  • Inject public-URL metadata. After the reskin (so the tripwire never scans injected content): the sync banner right after the doctype, " — Brad Lasater" appended to the title, and a head block with canonical URL, theme colour, robots, Open Graph / Twitter card tags, favicon, and the handbook-chrome.css link — all marked "Added by scripts/sync_docs.py; not present in the source repository."
  • Link back out. One ← bradlasater.com link is injected as the first item of nav.toc; on the one page without a sidebar it goes at the top of <body> with the hb-back--plain variant instead.
  • Delete orphans. Any file in handbook/ that upstream no longer has is removed. This is why hand edits are not merely overwritten but actively hunted down.

--check mode writes nothing and exits 1 listing stale and orphaned files — the CI-friendly form. Two caveats, both deliberate: it exits 0 when the source repository is not present (so it is safe on a machine where the private repo was never cloned), and it cannot detect drift it cannot see. No workflow in .github/workflows/ currently runs it; freshness is a discipline, not an enforced gate. Exit codes: 0 ok (or source absent), 1 stale under --check, 2 could not run — an unreadable file must not be reported as "stale".

Two-layer styling

The published handbook renders in the site's design system through two layers with disjoint ownership:

  • Layer 1 — the reskin (owned by sync_docs.py). Rewrites palette and font names inside the synced files themselves, so handbook/site.css, the inline SVG diagrams, and box-operations' inline styles all come out in OKLCH tokens and the site's faces. Handbook pages do not load /assets/css/site.css, so the tokens are copied as literals — there is nothing to inherit.
  • Layer 2 — assets/css/handbook-chrome.css (owned by hand, loaded last, never touched by the sync). Everything string replacement cannot express: selection colour, smooth scrolling, content links underlined at rest (the handbook's own stylesheet only underlines on hover), a :focus-visible outline, the site's inline-code chip treatment, the radius scale (10px containers, pill badges), and the injected .hb-back link — including the specificity fight to keep it from being styled as a chapter link by nav.toc a.

Consequence: if the site's :root palette ever changes, you must update three places by hand — COLOR_MAP in sync_docs.py, the literals in handbook-chrome.css, and the source theme upstream — or the handbook quietly drifts off-palette.

Conventions and gotchas

  • The sidebar is upstream's. Every handbook page carries the same nav.toc chapter list with exactly one class="active" on its own chapter; ingest adds an ol.sub of in-page anchors. This is authored in the source repo and copied verbatim — the sync only prepends the back link. Reorder chapters upstream, then re-sync.
  • box-operations.html is the exception. It documents machine state the repo cannot declare, keeps its own inline <style> (no handbook/site.css), and has no sidebar and no <main>. The sync's reskin still applies to its inline styles (its status-tag washes have their own COLOR_MAP entries), and handbook-chrome.css reaches it through body > selectors and .hb-back--plain. If you ever add a second sidebar-less page upstream, check both of those paths still hold.
  • A new upstream colour or font breaks the build — that is the feature. When the sync aborts on an unmapped value, decide whether it maps to a site token (COLOR_MAP / FONT_MAP) or is categorical (ALLOWED_SOURCE_COLORS); never just allowlist your way past a genuine theme leak.
  • The sync refuses a pre-bannered source. If a synced file ever lands back in the upstream repo (e.g. copied the wrong direction while debugging), transform_html() aborts rather than double-transforming. Strip the banner upstream, or fix your copy-paste.
  • Known sharp edges, unpatched. The audit lists five: an 8-digit hex hole in the leftover-colour scan, og:title double-escaping if an upstream title ever contains a raw entity, FONTS_URL_RE over-matching single-quoted hrefs, upstream subdirectories silently dropped by plan(), and --check passing on a typo'd source path. See audit item 50.
