Audit follow-ups (2026-09-02)

Findings from the full-repo audit (branch audit-2026-09-02). Everything that was a clear, safe bug was fixed in that branch; this file is the list of things deliberately left for later — larger refactors, design decisions, doc drift, and out-of-scope fixes. Grouped by area, roughly most-worth-doing first.

Do first (correctness / credibility)

  1. Run the handbook sync. python3 scripts/sync_docs.py --check reports handbook/404.html, handbook/ingest.html, handbook/knobs.html, and handbook/site.css stale vs. the upstream repo (pre-existing drift — new rate-limit/cronjob prose). Run python3 scripts/sync_docs.py and commit.
  2. README Analytics section is now false (README.md:184-190): still says analytics "is currently inert, CODE is an empty string", but assets/js/analytics.js:18 sets CODE = "bradlasater". Rewrite the section — a recruiter reading view-source should not see docs contradicting the code.
  3. README.md:72-73 — "every page loads analytics.js" is false: no handbook/*.html loads it (sync adds canonical/favicon/OG but not analytics) and journal-prompts.html doesn't either. Decide whether handbook pageviews should count (the most technical content on the site is currently invisible to the funnel), then reword. Handbook fix belongs in the source repo's template; journal-prompts needs one <script> line.
  4. SCHEMA.md:15-18 understates the append-only guarantee: says CI "diffs the file against the previous commit", but the validator walks every commit from a baseline ref and the workflow rejects force-pushes. State the stronger truth.
  5. Validate workflow doesn't trigger on schema edits (.github/workflows/validate-track-record.yml:18-28): add data/SCHEMA.md to the push and pull_request path filters so a contract change re-runs the validator.
  6. Stale ROADMAP items: .gitignore exists (ROADMAP.md:287-288); cv.pdf is shipped (ROADMAP.md:260-261); the footer-drift item cites build_site.py:210 for nav() — now at line ~218. Check boxes / fix refs.
  7. Confirm the Person JSON-LD employment claim (index.html): declares worksFor: Nift while the CV shows Ticketmaster ended Mar 2025 and the badge says "Part-time, concurrent". Accuracy matters on a recruiting site.

Build script (scripts/build_site.py)

  1. stamp() (:557) silently no-ops if a page loses its stamp markers and --check still passes — assert ≥1 substitution per static page and/or make the STAMPS regexes attribute-order tolerant.
  2. render_llms_log_section (:456) interpolates entry titles raw into Markdown — a [/] in a title breaks the llms.txt link. Add bracket escaping.
  3. MARKER regex (:73) excludes digits — a future BUILD:NAV2:START marker never matches. Widen [A-Z-]+ to [A-Z0-9-]+ (one character).
  4. Orphan cleanup (:634) deletes any log/*.html not in the planned set — a hand-authored page dropped into log/ is destroyed silently. Restrict deletion to files bearing a generated-by marker.
  5. Decide committer-date (%cI) vs author-date (%aI) semantics for last_modified before entries accumulate; also consider max(fragment_date, template_date) so template-only changes don't rewrite entry pages without bumping feed/sitemap dates.
  6. Single-pass lastmod: even cached, the build forks ~20+ git log calls. One git log --format=%cI --name-only pass would be O(1) subprocesses — worth it once entry count grows.
  7. Minor: render_entry passes an unused modified_human kwarg; duplicate meta keys silently overwrite (last wins) unlike the rest of meta validation.

Data contract / validator

  1. Timezone semantics of "future": date.today() is local; CI is UTC. A contributor east of UTC appending early morning gets a legit observation rejected. Pick a policy (explicit UTC, or 1-day tolerance) and document it in SCHEMA.md.
  2. Pass parse_constant= to json.loads in the validator so NaN/Infinity are invalid JSON outright (belt-and-braces over the new field checks).
  3. append_observation.py --mode default: after transitioning to live, the paper default makes every append fail until --mode live is passed. Default to the mode implied by mode_changes.
  4. Exit-code collision: the append script's docstring says 2 = "could not run", but argparse also exits 2 on usage errors. Map argparse errors to 1 or amend the doc.
  5. --note is silently ignored on plain appends (only meaningful with --mode-change) — error on the combination.
  6. Workflow: empty git merge-base (orphan branch) yields a confusing "cannot resolve ''" — handle explicitly (.github/workflows/validate-track-record.yml:69-72).

Frontend JS

  1. Commit a JS test harness for track-record.js — the audit verified the math with a dependency-free jsc + DOM-stub harness; today this 840-line correctness-critical file has zero automated tests. The harness approach runs on any macOS CI runner.
  2. Add a schema_version check in normalise() — one line (if (doc.schema_version !== 1) throw) so a future v2 contract fails loudly instead of rendering subtly wrong numbers.
  3. normalise() silently sorts out-of-order observations, masking a validator bypass — consider throwing instead (design decision).
  4. tr-days ("days live") depends on the viewer's clock/timezone — compute inception→latest-observation from the data file for a deterministic number.
  5. Fetch failure is terminal until manual reload — add a retry button or one automatic retry (needs an HTML change in vol/track-record.html).
  6. Factor the duplicated running-peak drawdown logic in computeStats() and buildSeries() into one helper; dedup overlapping mode_changes boundary markers (cosmetic).
  7. costShare shows "—" when cumulative gross P&L ≤ 0 even though costs are known — consider share of |gross| with a hint; "costs ate the edge" matters most exactly then.
  8. Analytics: verify whether the mailto contact-email event undercounts (same-tab navigation may cancel the request); if so use GoatCounter's callback pattern. Also add one line to the privacy comment noting anonymised click events are recorded.

Markup / accessibility / meta

  1. Add og:image:alt to the three vol/*.html pages (only pages missing it).
  2. vol/index.html:151 — <cite> wraps a person's name ("after Euan Sinclair"); the spec restricts <cite> to titles of works. Use <footer> or a span.
  3. Methodology stats table: promote first-column <td>s to <th scope="row"> so screen readers announce the statistic name per row.
  4. Wrap role date ranges in <time datetime="YYYY-MM"> on index.html / cv.html — machine-readable semantics for parsers and assistive tech.
  5. Decide en-GB vs en-US: prose is British but og:description, JSON-LD (inLanguage: en-US, og:locale en_US) use American spelling. Deliberate for US recruiters, or unify?
  6. MinTRL hint "Returns needed at 95%" (vol/track-record.html:231) reads as performance to non-specialists; the JS renders an observation count. Consider "Observations needed at 95%".
  7. journal-prompts.html body content has no <main> landmark (only HTML file without one; minor — local-only, noindexed).
  8. content/log/TEMPLATE.html.example is unreferenced and has drifted from the real inline template in build_site.py (lacks the analytics tag and more) — delete it or regenerate from the real template.

CSS / design

  1. Handbook print output is unreadable: no @media print in the synced handbook/site.css (52 hard-coded light-on-dark rules), so printed pages render grey-on-white with the sidebar. Fix belongs in assets/css/handbook-chrome.css: hide nav.toc/.hb-back, force dark text.
  2. Generate a 1200×630 og-image variant of assets/deja.jpg for the 404 page — 332×152 is below every platform's recommended size, some scrapers ignore it.
  3. 404 polish: hero__bio max-width and the 680px .error__figure don't align left edges exactly; a shared wrapper width in error.css would tighten it.
  4. Move one-off inline styles (style="margin-top: var(--sp-4);", hero h1 size on cv.html) into site.css utility/modifier classes.
  5. Verify the JS clamps .chart__tip at chart left/right edges on narrow viewports (potential mobile overflow; CSS alone can't confirm).
  6. README vs CSS off-by-one: @media (max-width: 56rem) stacks the header at 896px; README says "below 56rem". Reword README or use 55.99rem.

  2. Add paths-ignore for feed.xml/sitemap.xml/llms.txt in build-site.yml — the bot's own rebuild commit currently re-triggers a guaranteed no-op run.
  3. Mention the Atom feed in llms.txt (one line under "## Data").
  4. Document the pre-commit re-stage dance in README (hook regenerates files but doesn't stage them; commit fails with "files were modified" until re-added).
  5. notes/baseline-audit.md: many listed gaps are now fixed — add a "status as of 2026-09-02" header so readers don't treat resolved gaps as open.
  6. When the first log entry ships: harmonise the log-index footer (3 links) with generated entry-page footers (6 links), and decide the canonical footer convention (homepage has 8, subpages 4–5) — codify in README.
  7. article:modified_time offsets are -06:00 sitewide (stamped from git). For a New-York-based candidate this reads oddly — consider normalising the zone in the build script.
  8. sync_docs.py hardening (from audit): 8-digit hex hole in the reskin colour map (#RRGGBBAA partially rewritten); og:title double-escape if an upstream title ever contains a raw entity; FONTS_URL_RE over-matches single-quoted hrefs; upstream subdirectories silently dropped by plan(); --check passes when the source path is typo'd (--require-source flag?).
